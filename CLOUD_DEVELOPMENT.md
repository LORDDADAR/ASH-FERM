## Окружение

Используйте Node.js 24 LTS и Bash. Установка npm-пакетов не требуется.
Проверка окружения и синтаксиса:

```sh
bash scripts/cloud-setup.sh
```

Запуск из корня репозитория:

```sh
node serve.cjs
```

Адрес внутри окружения: `http://127.0.0.1:8080/`.
Проверка работы в подпапке: `http://127.0.0.1:8080/farm/`.
Необязательная переменная `PORT` меняет порт:
`PORT=8081 node serve.cjs`. `.env` автоматически не загружается.
Другие переменные, секреты и база данных текущему коду не нужны.

На телефоне адрес `127.0.0.1` относится к самому телефону. Для просмотра
облачного сервера нужен предоставляемый платформой preview/port forwarding
или браузер внутри облачного компьютера. Сервер слушает loopback; при
необходимости отдельную настройку привязки адреса следует согласовать
с механизмом preview. Публиковать сервер разработки в интернет не требуется.

## Подключение и работа с телефона

1. Откройте `https://chatgpt.com/codex` под своим аккаунтом.
2. Подключите GitHub, если он ещё не подключён, и разрешите доступ
   к `LORDDADAR/ASH-FERM`.
3. Для постоянной настройки откройте **Settings → Codex Cloud → Environments**
   в веб-интерфейсе или приложении для компьютера. Создайте облачное окружение
   с существующим репозиторием и Node.js 24. В настройке установки, если она
   предусмотрена интерфейсом, укажите `bash scripts/cloud-setup.sh` после
   сохранения этого файла в GitHub. Секреты не добавляйте: проект их не требует.
4. Проверьте отчёт настройки и опубликуйте окружение для последующего выбора.
   Названия кнопок могут отличаться; если мобильный интерфейс скрывает
   настройку, используйте полную версию сайта в браузере.
5. На телефоне выберите опубликованное **облачное** окружение и репозиторий.
   Подключение к домашнему компьютеру для этой схемы не нужно.
6. Пример задания: «В репозитории LORDDADAR/ASH-FERM создай отдельную ветку,
   внеси [описание изменения], выполни bash scripts/cloud-setup.sh,
   проверь игру, покажи diff и создай pull request. Не меняй main напрямую».
7. Просмотрите diff и проверки в PR, затем выполните Merge в GitHub.
   Убедитесь, что нужные изменения действительно сохранены в GitHub:
   несохранённая рабочая папка облачной задачи не заменяет репозиторий.

Актуальные инструкции OpenAI:
https://learn.chatgpt.com/docs/environments/cloud-environments
и https://help.openai.com/en/articles/20001545-using-codex-cloud.
Наличие доступа к Codex и конкретных возможностей зависит от аккаунта.
Этот документ не означает, что постоянное окружение уже создано или опубликовано.

## Однократная проверка домашней папки

До окончательного перехода выполните в существующей папке игры:

```sh
git status --short --branch --untracked-files=all
git fetch origin
git branch -vv
git log --oneline --branches --not --remotes
git ls-files --others --exclude-standard
git ls-files --others --ignored --exclude-standard
```

Последняя команда показывает и игнорируемые файлы: среди них могут быть
важные локальные данные. Ничего не удаляйте и не отправляйте автоматически.
Сравните текущую ветку с её upstream; проверьте и остальные рабочие папки,
если локальное приложение использовало worktree. Не используйте `git add .`
вслепую. Добавляйте только проверенные исходники, затем сделайте commit/push
в свою ветку. Значения токенов, `.env`, дампы с персональными данными и
приватные ключи в GitHub не отправляйте. Не присылайте их в чат.

`.gitignore` защищает от обычного случайного добавления секретов, но не
исключает уже отслеживаемые файлы и не очищает историю. Если секрет когда-либо
был опубликован, его нужно отозвать у поставщика; переписывание истории
требует отдельного решения. Полный аудит истории секретов здесь не заявляется.

## Сохранения и публикация игры

Прогресс хранится в `localStorage` браузера игрока, ключ зависит от пути URL.
Он не находится в GitHub и не переносится вместе с исходниками. Смена домена,
пути или браузера может показать новую ферму. Для проверки пользуйтесь
отдельным профилем и не очищайте данные основного игрового адреса.

Для текущей статической игры подходит GitHub Pages. Проверьте существующие
**GitHub → Settings → Pages** и адрес публикации, прежде чем менять настройки.
Если Pages настроен на `main / (root)`, изменения после merge будут опубликованы
после успешного развёртывания Pages. Проверьте результат в Actions/Pages.
Наличие Pages в настройках репозитория само по себе не подтверждает развёртывание.
Service worker хранит ресурсы в кэше; проверяйте обновление после переоткрытия
игры и при изменении ресурсов учитывайте версию кэша в `sw.js`.

Облачная разработка и GitHub Pages работают при выключенном домашнем ПК.
Codex Cloud не является круглосуточным хостингом Telegram-бота. Если отдельный
бот сейчас работает на домашнем ПК, для его непрерывной работы потребуется
отдельный сервер/хостинг и безопасная настройка токена вне репозитория.
